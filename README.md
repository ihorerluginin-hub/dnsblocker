# Блокировщик рекламы (DNS-only VPN, без root)

Локальный блокировщик рекламы для Android: поднимает штатный `VpnService`,
перехватывает DNS-запросы и заворачивает рекламные/трекерные домены.
Root не нужен, трафик не проксируется, батарея почти не тратится.

## Как работает

- VPN-интерфейс получает фейковый DNS-сервер `10.111.222.3` (и IPv6 `fdae4:b1d7:6c61::3`),
  который система и использует как свой DNS, пока VPN активен.
- В туннель дополнительно заведены /32-маршруты популярных публичных DNS
  (8.8.8.8, 1.1.1.1, 9.9.9.9, 77.88.8.8, …), куда приложения пишут адреса напрямую.
- Из туннеля обрабатывается только UDP/53:
  - домен в блок-листе → A получает `0.0.0.0`, AAAA — `::`, прочие типы — `NXDOMAIN`;
  - остальное — прозрачная пересылка на DNS текущей сети (или 1.1.1.1/8.8.8.8)
    через защищённый `protect()`-сокет (без зацикливания).
- TCP в туннель не пропускается: DoT (порт 853) к заведённым адресам просто умирает,
  и приложения откатываются на обычный DNS, который фильтруется.
- Весь остальной трафик мимо туннеля — проксирования нет.

## Сборка

```
set "JAVA_HOME=C:\Program Files\Android\Android Studio\jbr"
gradlew.bat assembleDebug
```

Готовый APK: `app\build\outputs\apk\debug\app-debug.apk` (~0,9 МБ, внешних зависимостей нет).

Установка на устройство (устройство подключено по adb, отладка включена):

```
adb install -r app\build\outputs\apk\debug\app-debug.apk
```

## Первый запуск

1. Открыть приложение → «Включить блокировку».
2. Согласиться на системный запрос VPN-соединения (один раз).
3. Разрешить уведомления (для фонового сервиса).
4. В фоне докачается полный список StevenBlack hosts (~10 МБ, ~200 000 доменов);
   до этого работает встроенный стартовый список (~150 доменов).

Проверка: открыть любой сайт с рекламой, либо https://doubleclick.net — не должен открываться.
Счётчики запросов/блокировок видны на главном экране.

## Списки

- Кнопка «Обновить список блокировки» — перекачка с
  `https://raw.githubusercontent.com/StevenBlack/hosts/master/hosts`.
- Парсер понимает hosts-формат (`0.0.0.0 домен`), простые домены в строку
  и минимум правил Adblock (`||домен^`). Блокируется домен и все его поддомены.
- Свой список: положить файл `blocklist.txt` во внутреннюю память приложения
  (`/data/data/com.biologigor.dnsblocker/files/blocklist.txt`).
- Исключения: файл `whitelist.txt` в той же папке (по одному домену на строку) —
  домен и его поддомены не блокируются.

## Ограничения (честно)

- **DoH в браузерах**. Если в Chrome/Edge включён «Безопасный DNS» — браузер ходит
  в DNS по HTTPS мимо фильтра. Отключите его в настройках браузера.
- **Частный DNS (Private DNS) в строгом режиме** — обходит фильтр. Ставьте
  «Автоматически» или отключите (Настройки → Сеть → Частный DNS).
- Приложения с собственным DoT/DoH к адресам, не заведённым в туннель, тоже пройдут мимо.
- Блокировка доменная: то, что раздаётся с того же хоста, что и контент, не режется.

## Верификация

- Сборка: `gradlew assembleDebug` — успешно (AGP 9.4.1, Kotlin 2.0.21, Gradle 9.6.0).
- Ядро (DnsPacket.kt, Packet.kt) прогнано смоук-тестом на JVM
  (`tools/smoketest/Main.kt`): 47 проверок — разбор запросов, сборка ответов
  (A/AAAA/NXDOMAIN/SERVFAIL), валидация IPv4/IPv6 заголовков и UDP-чексумм — все прошли.
- Проверено на устройстве (TECNO KL8, Android 14): туннель поднимается,
  `google.com`/`ya.ru` резолвятся через обычный DNS сети, домены из списка
  (`doubleclick.net`, `hotjar.com`, `appsflyer.com`) блокируются,
  счётчики запросов/блокировок в UI тикают.
- Цикл «включить → выключить → включить» проверен на устройстве многократно:
  сервис полностью уничтожается, tun0 сносится, повторное включение
  поднимает VPN заново.

### Грабли, на которые наступили (важно для доработок)

1. **Адрес DNS-сервера не должен совпадать с адресом TUN-интерфейса.**
   Запросы на адрес самого интерфейса ядро считает локальными и доставляет
   на loopback — в туннель они не попадают никогда. Поэтому интерфейс
   `10.111.222.3`, а DNS `10.111.222.4` (аналогично для IPv6).
2. **`Builder.setBlocking(true)` обязателен.** На части устройств fd туннеля
   в non-blocking: `read()` отдаёт 0 вместо ожидания пакета, и цикл чтения
   мгновенно завершается.
3. **Валидный IPv6**: группы адреса — максимум 4 hex-цифры
   (`fdae4:...` — мусор, `fdae:...` — ок); `addAddress()` бросает
   `IllegalArgumentException` и сервис тихо умирает.
4. **`Context.stopService()` может игнорироваться** прошивкой для
   foreground-VPN-сервиса (замечено на HiOS/TECNO): сервис продолжает жить.
   Поэтому выключение — через явный intent `ACTION_STOP` в сервис, где
   выполняются `stopTunnel() + stopForeground(REMOVE) + stopSelf()`.

## Структура

```
app/src/main/java/com/biologigor/dnsblocker/
  VpnTunnelService.kt  — VpnService, чтение TUN, пересылка/блокировка, уведомление
  DnsPacket.kt         — разбор DNS-запросов, сборка ответов
  Packet.kt            — сборка IPv4/IPv6+UDP пакетов, чексуммы
  BlocklistManager.kt  — загрузка/парсинг/обновление списков
  MainActivity.kt      — UI: вкл/выкл, статистика, обновление списка
tools/smoketest/       — JVM-смоук-тест ядра
```
